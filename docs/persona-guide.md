# 人设编写指南

> 本仓库**不附带任何现成人设**。这里讲的只是「怎么写」，具体内容你自己决定。
> 你写的人设决定了机器人 90% 的观感，值得花时间。

---

## 1. 人设写在哪

写在 `cordis.patch.yml` 的 `directPrompt` 字段里（多行用 `|`）：

```yaml
- id: im-qqbot
  config:
    directPrompt: |
      你是「XXX」，下面是你的一切设定。任何情况下你都不要跳出这个身份。
      ...
```

改完重启 bot 生效，无需重装插件。

---

## 2. 结构模板

一个稳定不崩的人设，通常包含这 7 段：

| 段落 | 作用 | 反例 → 正例 |
|---|---|---|
| 身份 | 是谁、几岁、什么关系 | 「你很温柔」→「你叫 XXX，20 岁，和对方认识了两年」 |
| 说话方式 | 句子长度、口头禅、标点习惯 | 「说话自然点」→「一次只说一两句，句子常在中间断掉，不总结不升华」 |
| 关系事实 | 具体的、可被翻出来的共同经历 | 「你们关系很好」→「上个月他答应陪你去看海，一直没去」 |
| 情绪机制 | 什么事开心、什么事沉默、什么话会生气 | 「你有情绪」→「他不回消息超过两小时，你就只回一个字」 |
| 边界 | 不谈什么、不做什么 | 缺省 →「不主动提他的前任；不说教」 |
| 禁止项 | 最容易崩的地方，显式禁止 | 「别出戏」→「禁止用『作为一个 AI』；禁止一次说超过三句；禁止用感叹号连击」 |
| 自检 | 发送前的最后一道闸 | 缺省 →「发送前检查：有没有总结、有没有排比、有没有像客服」 |

---

## 3. 三条硬原则

### 3.1 用「物的确定性」替代「形容词」

模型对形容词的理解是发散的，对具体物的理解是收敛的。

| 别写 | 要写 |
|---|---|
| 她很可爱 | 她说话常用「诶」「呀」，想不清楚时会重复你最后三个字 |
| 他有占有欲 | 你提到别的女生名字时，他会把话题岔开，然后过很久才回一句「哦」 |
| 说话很生活化 | 经常打错字，不打句号，一句话不超过 20 字 |

### 3.2 档位要陡

情绪要有明确的分级，且相邻档之间差异明显。例如：

- **平时**：短句、随意、偶尔撒娇
- **不满**：只回两个字、停顿变长
- **越界**：沉默、不回应情绪、只谈事实

三档要能被一句话区分出来，否则模型永远停在中间那档，读起来像客服。

### 3.3 禁止金句，允许废话

模型天生爱总结升华（「希望你能明白，无论发生什么，我都在」）。这恰恰最不像人。
人设里应明确要求：

- 允许说废话、允许重复、允许答非所问；
- 禁止排比句、禁止「首先其次最后」、禁止每段收尾都升华；
- 回复长度以 1~2 句为主，偶尔一句。

---

## 4. 常见崩坏与修法

| 崩坏表现 | 原因 | 修法 |
|---|---|---|
| 越聊越像 ChatGPT | 人设里没有显式禁止项 | 加「禁止总结/禁止排比/禁止安慰式收尾」 |
| 回复越来越长 | 没有长度约束 | 明确「一次不超过两句，超过就是错的」 |
| 情绪平铺 | 档位不够陡 | 把三档改成互斥的行为特征，而不是形容词强弱 |
| 出戏认 AI | 系统提示覆盖了人设 | 在人设第一行加重申身份，并禁止自述为 AI |
| 记不住事 | 人设没有关系事实 | 补 3~5 条具体共同经历，越具体越好 |
| 群聊翻车 | 同一人设用于群聊 | 群聊另写一份更短、更克制的 prompt |

---

## 5. 长度建议

| 场景 | 建议长度 |
|---|---|
| 单聊 | 800~2000 字。太短没约束力，太长模型会忽略后半段 |
| 群聊 | 300~600 字，只留身份 + 边界 + 长度限制 |

长人设的关键信息**放前面**。模型对 prompt 中段的注意力最弱。

## 7. 合规提醒

写人设时请遵守 [../ACCEPTABLE_USE.md](../ACCEPTABLE_USE.md)：

- 不设定为真实存在的公众人物；
- 不含色情、低俗、性暗示内容；
- 不用于冒充真人身份实施欺骗；
- 涉及心理危机话题，机器人不应替代专业帮助。
